# 收割（Harvest）动画调查与修复方案

日期：2026-08-22。参考源码：`D:\plumamod2\Slay the Spire 2 0.111.0`（只读）。

## 一、现象

Harvest（X 费罕见攻击牌，切割）代码里调用了
`CreatureCmd.TriggerAnim(creature, "Skill_2_Start/Attack/End", ...)`，
但实际运行时只看到默认攻击动画，Skill_2_* 自定义动画完全没有播放。

## 二、根因：触发器未注册，状态机静默丢弃

玩家角色的战斗动画不是"按名字直接播放"，而是走 `CreatureAnimator` 状态机：

1. `NCreature.cs:178` 用 `Entity.Player.Character.GenerateAnimator(...)` 构建动画器。
2. `CharacterModel.GenerateAnimator`（CharacterModel.cs:247-265）只注册了这些触发器：
   `Idle`、`Relaxed`、`Dead`、`Cast`、`Attack`、`Hit`、`PowerUp`（来自 `AnimationStates` 列表）。
3. `CreatureAnimator.SetTrigger`（CreatureAnimator.cs:67-78）：在 anyState 和当前状态里找
   名为 trigger 的分支，**找不到就静默返回，不报错也不播放**。

因此 `TriggerAnim("Skill_2_Start")` 等调用全部被静默丢弃 → 自定义动画不播放。

同时，`DamageCmd.Attack` 的 `FromCard` 会自动设置 `_attackerAnimName = "Attack"`
（AttackCommand.cs:230），而 `PlumaCharacter.AttackAnimDelay = 0f`，
于是每段攻击都触发默认 Attack 动画且不等待 → 玩家看到的"默认/原本的攻击动画"。

**动画名已确认存在**：`pluma/images/spineAni/sum/char_421_crow_summer_9.json`
与 `ori/char_421_crow.json`（两个皮肤骨架）都含有：

| 动画名 | 名义时长 |
| --- | --- |
| Skill_2_Start | 0.333s |
| Skill_2_Attack | 0.667s |
| Skill_2_End | 0.333s |
| Skill_2_Idle | 1.33s |

（名义时长通过递归扫描 JSON 时间轴最大值得到。）

## 三、等待机制：TriggerAnim 是"触发 + 固定等待"

`CreatureCmd.TriggerAnim`（CreatureCmd.cs:967-1000）：

```csharp
creatureNode.SetAnimationTrigger(triggerName);
await Cmd.CustomScaledWait(Mathf.Min(waitTime * 0.5f, 0.25f), waitTime);
```

- 它**会等待**，但等的是固定时长（快模式 min(wait*0.5, 0.25)，标准模式 wait），
  不是等动画真实播完。
- `Cmd.CustomScaledWait(fast, standard)`（Cmd.cs:54-72）按游戏 FastMode 设置
  （Fast/Normal/Instant）选择等待量，Instant 模式跳过。

**可等待的替代机制**：

- `NCreature.SetAnimationTrigger` 同步生效，随后
  `NCreature.GetCurrentAnimationLength()`（NCreature.cs:544-547）即可拿到
  当前动画的名义时长。
- `AttackCommand.AfterAttackerAnim(Func<Task>)`（AttackCommand.cs:389-393）：
  回调在攻击动画触发之后、命中 VFX/伤害之前执行 → 可用来实现
  "动画播完 → 造成该段伤害"。

## 四、动画速度 API（已从源码确认）

- `NCreature.SpineAnimation` 是公开属性（NCreature.cs:106），类型 `SpineAnimationAccess`。
- `SpineAnimationAccess.SetTimeScale(float)`（SpineAnimationAccess.cs:50-53）
  → `MegaAnimationState.set_time_scale`，设置该 AnimationState 的默认时标，
  影响之后触发/排队的动画。
- 视觉播放时长 = 名义时长 ÷ 时标。等待时应按 `len / speed` 计算。
- 多人模式安全：时标只作用于本地角色的 Spine 节点，是纯视觉效果，
  不进入同步数据；用完必须恢复 1f。

## 五、渐入佳境层数与升级判断

- Power 类名：`FlowState`（Scripts/Powers/FlowState.cs）。
- 层数读取：`creature.GetPowerAmount<FlowState>()`（返回 int，
  Creature.cs:596；项目内 FullSpeedSlash.cs:57、FeatherWave.cs:71 同款用法）。
- 升级判断：`base.IsUpgraded`（CardModel.cs:784；项目内 BladeForm.cs 同款用法）。

## 六、速度公式（用户已确认）

S = min(10, (1 + 3%×层数) / 0.65)（未升级）；升级后分母为 0.5。
即字面播放速度倍率，倍率封顶 10x。
（3% 与 FlowState 每层 +3% 攻击加成的数值一致。）

| 层数 | 未升级 S | 升级 S | Attack 段实际时长（0.667s） |
| --- | --- | --- | --- |
| 0 | 1.54 | 2.0 | 0.43s / 0.33s |
| 10 | 2.0 | 2.6 | 0.33s / 0.26s |
| 50 | 3.85 | 5.0 | 0.17s / 0.13s |
| 100 | 6.15 | 8.0 | 0.11s / 0.08s |
| 184+（未升级）/ 134+（升级） | 10（顶格） | 10（顶格） | 0.07s / 0.07s |

## 七、修复方案

### 1. PlumaCharacter.cs：注册 Skill_2 触发器

覆盖 `CharacterModel.AnimationStates`（protected virtual），在原有列表后追加：

```csharp
protected override List<(AnimState, string)> AnimationStates => base.AnimationStates
    .Concat(new (AnimState, string)[]
    {
        (new AnimState("Skill_2_Start"), "Skill_2_Start"),
        (new AnimState("Skill_2_Attack"), "Skill_2_Attack"),
        (new AnimState("Skill_2_End"), "Skill_2_End"),
    }).ToList();
```

- 原版 `GenerateAnimator` 会遍历该列表，为每个条目注册 anyState 触发器，
  并自动把"动画播完后的下一个状态"接到 idle_loop / low_health_loop（保留低血量条件分支）。
- RitsuLib 的 `CharacterCreatureAnimatorRuntimeFactoryPatch`
  （ModModelRuntimeGodotFactoryPatches.cs:558-614）在角色未提供自定义动画器时
  回落到原版 `GenerateAnimator`，所以这条路径有效。
- 副作用：所有调用 `TriggerAnim("Skill_2_*")` 的卡牌都会受益。

### 2. Harvest.cs：重写 OnPlay 动画流程

```
x = ResolveEnergyXValue(); x<=0 直接返回
Apply<HarvestTempPower>                        // 不动
f = creature.GetPowerAmount<FlowState>()
S = min(10, (1+0.03f) / (IsUpgraded ? 0.5 : 0.65))
node.SpineAnimation.SetTimeScale(S)            // try/finally 恢复 1f
PlayAndWait(Skill_2_Start)                     // 触发 + 等 len/S 播完
for i in 0..x-1:
    DamageCmd.Attack(DynamicVars.Damage.BaseValue)
        .FromCard(this, cardPlay)
        .TargetingAllOpponents(CombatState)    // AOE 逻辑不动
        .WithAttackerAnim("Skill_2_Attack", 0) // 覆盖默认 Attack 动画
        .WithAttackerFx(sfx: Character.AttackSfx) // 保留攻击音效（自定义名不触发角色音效分支）
        .AfterAttackerAnim(读当前动画时长 → 等 len/S)  // 动画播完才结算伤害
        .WithHitFx("vfx/vfx_attack_slash")     // 不动
        .Execute(choiceContext)
PlayAndWait(Skill_2_End)
finally: SetTimeScale(1f); Remove<HarvestTempPower>  // 原逻辑保留
```

等待语义与原版 `TriggerAnim` 一致：`Cmd.CustomScaledWait(min(wait*0.5, 0.25), wait)`，
标准模式等满动画时长，快模式截断，Instant 模式跳过。
节点不存在（测试/非战斗）时 `GetCurrentAnimationLength()` 返回 0 → 不等待，安全。

### 3. 明确不改的东西

- 伤害数值（`DynamicVars.Damage.BaseValue` + HarvestTempPower 层数）
- X 费逻辑（`HasEnergyCostX` / `ResolveEnergyXValue`）
- 切割关键词、AOE 目标逻辑（`TargetingAllOpponents`）
- 不用 `new Random()`；dealer 始终由 `FromCard` 设置（无 null dealer）

### 4. 已知取舍

- `Skill_2_Idle` 未使用：End 播完后按原版行为回到普通 idle。
- 高流层时动画极快（上限 10x），属用户已确认的预期。
